# Feature Specification: Playing Othello Variant

**Feature Branch**: `001-playing-othello-variant`

**Created**: 2026-09-15

**Status**: Draft

**Input**: User description: "十字キーで移動・エンターでコマを置くオセロらしきゲームを othello.exe で遊べるようにしてほしい。ボードを 90°回転させるターンがある変則ルール。あとは任せる。"

## User Scenarios & Testing (mandatory)

### User Story 1 - 石を置いて反転させる (Priority: P1)

オセロの基本動作：プレイヤーが交互に石を置き、相手の石を自分の色の石で挟むと反転して自分の色になる。

**Why this priority**: ゲームの根本動作。遊ぶためにはまずこれが不可欠。

**Independent Test**: 初期盤面が正しく表示され、石を配置したときに挟まれた相手石が反転することをコンソール上で確認できる。単体テストでゲームロジックを検証し、統合テストで CLI 入力を再現して確認できる。

**Acceptance Scenarios**:

1. **Given** 初期盤面（中央 4 マスに黒・白が交互に配置された 8×8 盤）、**When** 有効な位置に石を置く、**Then** 挟まれた相手石が全て反転し、盤面が更新される。
2. **Given** 反転可能な方向が複数ある局面、**When** 石を置く、**Then** 全ての方向で挟まれた石が反転する。
3. **Given** 反転しない位置に石を置こうとした、**Then** 無効として却下され盤面は変化しない。
4. **Given** 置ける場所が無いターン、**Then** 相手に手番が移る（パス）。

---

### User Story 2 - ボードを 90° 回転させて遊ぶ (Priority: P1)

自分のターンでは「石を置く」か「時計回りに 90° ボード回転」のどちらか一方だけを行える。回転ターンでは石を置かない。両プレイヤーが回転ターンを使用できる。石も盤面とともに回転する。

**Why this priority**: このプロジェクトの「変わった」核心要素。遊びの魅力を決める。

**Independent Test**: 回転コマンド実行で盤面表示が 90° 時計回りに変わり、石の座標関係もそれに応じて変化することを確認できる。回転の前後で反転可能方向が変化することを単体テストで検証できる。

**Acceptance Scenarios**:

1. **Given** 任意の盤面、**When** プレイヤーが回転ターンを選択、**Then** 盤面が時計回りに 90° 回転し、ターン終了（石は置かれない）。
2. **Given** 回転後の盤面、**When** 次のターンで石を置く、**Then** 回転結果を反映した盤面上で反転判定が行われる。
3. **Given** 石が配置されている盤面、**When** 回転、**Then** 石も一緒に回転する（座標変換が行われる）。
4. **Given** 両プレイヤー交代中、**When** いずれかのプレイヤーが回転ターンを選択、**Then** そのターンでは配置が行われず、相手の手番になる。

---

### User Story 3 - 十字キーで移動しエンターで配置する CLI 操作 (Priority: P1)

コンソール上でカーソル移動に十字キー、配置確定にエンターを使う。カーソルが盤面上の有効なマスを指す。

**Why this priority**: 遊びやすさ・直感性のために必要。MVP では必須の操作性要素。

**Independent Test**: キー入力シーケンスを再現して、カーソル位置が正しく移動し、エンターで選択位置が配置対象になることを統合テストで検証できる。無効な操作（盤面外など）はエラーなくハンドリングされる。

**Acceptance Scenarios**:

1. **Given** ゲーム開始直後、**When** 上下左右キーを押す、**Then** カーソルが盤面内で対応する方向に移動する（盤面外へは移動しない）。
2. **Given** カーソルが置けるマスを指している、**When** エンターを押す、**Then** そのマスに石が置かれる（置けないマスの場合は配置されない）。
3. **Given** カーソルが盤面の端を指している、**When** さらに端方向のキーを押す、**Then** カーソルは端で止まる（オーバーフローしない）。

---

### User Story 4 - 実際に 2 人で遊べる状態 (Priority: P1)

2 人交代でプレイでき、勝敗が決まるまで進められる。勝敗結果が表示される。

**Why this priority**: 「遊ばせて確認したい」という要求を保障するため。

**Independent Test**: 石置きと回転を交えたシーケンスを E2E テストで再現し、最終的に石数で勝敗が出ることを確認できる。手動でもコンソール上で遊べる。

**Acceptance Scenarios**:

1. **Given** 初期盤面から開始、**When** 両プレイヤーが交互に石を置く（必要ならば回転ターンを挟む）、**Then** ゲームは継続し、盤面が更新されていく。
2. **Given** 盤面が埋まるか双方がパスした、**When** 最終状態になる、**Then** 石数を比較して勝敗が表示される（引き分けもあり得る）。
3. **Given** 初期盤面、**When** 一定数の手を進める、**Then** 中間状態でも残り駒数・現在のプレイヤー表示など遊び続けられるのに必要な情報が提示される。

---

### Edge Cases

- 回転によって反転可能方向が変化した結果、それまでは置けなかった場所に置けるようになるケース
- 回転しても石が盤面からはみ出ないこと（座標変換の境界条件）
- 入力が極端に早い場合・リピート入力でのカーソル制御の一貫性
- パス連発による終局判定の正しさ
- 石が完全に無くなるあるいは埋まりきった状態での勝敗表示

---

## Requirements (mandatory)

### Functional Requirements

- **FR-001**: システムは 8×8 の盤面を管理し、各マスに「空・黒・白」の状態を持ち、初期配置（中央 4 マス交互）を正しく構築できる。
- **FR-002**: システムは有効な石配置を判定し、置けた場合に四方向（上下左右）で挟まれた opponent 石を反転できる。
- **FR-003**: システムは「石を置く」か「ボードを時計回りに 90°回転させる」のいずれかの手番アクションを許可し、回転時には石を置かせない。
- **FR-004**: 回転時には盤面上のすべての石も座標変換に伴い回転する。
- **FR-005**: システムはターン交代を管理し、置ける場所がない場合はパスして相手の手番に移る。
- **FR-006**: システムはゲームの終局（盤面埋まり／双方パス）を判定し、石数で勝敗を表示する（引き分けの可能性を含む）。
- **FR-007**: CLI は十字キーによるカーソル移動およびエンターによる配置選択を受け付け、盤面外移動を防止する。
- **FR-008**: ユニットテストカバレッジ 90% 以上、主要フローに対する E2E テストが存在する。

### Key Entities

- **Board**: 8×8 のマス目の集合。各マスは空・黒・白を持つ。回転操作により座標系が変換される。
- **Stone / Disc**: 色（黒／白）の属性を持つゲーム駒。盤面上の位置と組み合わせて反転対象判定に使われる。
- **Turn / GameState**: 現在手番のプレイヤー、盤面、カーソル位置（CLI 用）、終了したかどうかなどを保持する。
- **Cursor**: CLI 用に盤面上の注目位置を指すカーソル（盤外には出ない）。

## Success Criteria (mandatory)

### Measurable Outcomes

- **SC-001**: ユニット＋統合テストでコードカバレッジ 90% 以上を達成する（`pytest-cov`等で測定）。
- **SC-002**: 石配置→反転→勝敗までの典型フローが E2E テストで成功する。
- **SC-003**: 回転ターンを使用したゲームシーケンスが E2E テストで成功する（盤面回転＋その後反転関係の変化が正しい）。
- **SC-004**: キー入力（十字キー＋エンター）をシミュレートした統合テストで CLI 操作が正しく動く。
- **SC-005**: 実際に 2 人で交代しながら遊べる状態になり、終了時に勝敗が提示される。

## Assumptions

- プラットフォームは Windows コンソールを想定し、`msvcrt` を用いてキー入力を処理する。
- 技術スタックは Python 3 + pytest とする（実行の簡便さと TDD／カバレッジ・E2E の容易性から）。
- 拡張（特殊駒、ミッション、盤面サイズ可変等）は本仕様では扱わず、別 feature とする。
- 操作性は「十字キーでカーソル移動＋エンターで配置確定」を基本とし、WASD キーもサポートする。
- ゲームエンジンの内部表現は CLI 表示と分離し、テスト可能性を確保する。
- 最終成果物は PyInstaller を用いて単一の `.exe` ファイルとして配布可能にする。
